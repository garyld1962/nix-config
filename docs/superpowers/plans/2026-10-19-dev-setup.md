# dev-setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One PowerShell command turns a fresh Windows laptop into an Ubuntu 26.04.1 WSL distribution running the shared bootstrap, plus a companion reset script.

**Architecture:** `scripts/wsl-common.ps1` holds every reusable function (pure helpers first, `wsl.exe` wrappers second) and is dot-sourced by `dev-setup.ps1`, `dev-reset.ps1`, and the rebased lab. The two entry scripts are linear stage orchestration with no logic of their own worth unit-testing. Pure helpers get Pester 5 tests; everything PowerShell goes through PSScriptAnalyzer.

**Tech Stack:** Windows PowerShell 5.1 (the `irm | iex` target; no PowerShell 7 features), Pester 5, PSScriptAnalyzer, `wsl.exe`, `curl.exe`, bash inside the distro.

**Spec:** `docs/superpowers/specs/2026-10-19-dev-setup-design.md`

## Global Constraints

- All PowerShell runs on Windows PowerShell 5.1: no `??`, no ternary, no `-Parallel`, no `[Text.UTF8Encoding]::new` outside functions that set `$OutputEncoding` (that one is fine in 5.1).
- `$ErrorActionPreference = 'Stop'` in every script; every `wsl.exe` call checks `$LASTEXITCODE`.
- Image: `https://releases.ubuntu.com/26.04.1/ubuntu-26.04.1-wsl-amd64.wsl`, verified against that directory's `SHA256SUMS`. Downloads go to `.partial`, renamed only after checksum success.
- Username regex `^[a-z][-a-z0-9_]*$`, max 32 chars, not `root`.
- Password: `Read-Host -AsSecureString` twice, plaintext exists only from confirmation to end of Stage 3, variable set to `$null` afterwards. Never written to disk, argv, or console.
- Marker `/etc/dev-setup-distro` content: `dev-setup v1 <user>`. Lab marker: `Ubuntu-Nix-Test blank baseline v2`.
- Windows floors: build 19041 for WSL 2, build 22621 and WSL 2.0.0 for mirrored networking.
- Install dir `%LOCALAPPDATA%\WSL\<Distro>`; image cache `%LOCALAPPDATA%\WSL\images`.
- Spec deviation (verified 2026-10-19 on this machine): `bash -s` runs the first stdin line as script, so the stdin payload is `IFS= read -r SECRET`, then the secret line, then the script. Commands in the script that could read stdin are wrapped in `{ ... } </dev/null` so they cannot eat script lines.
- Spec deviation: `Get-WslDistros` is named `Get-WslDistroList` (PSScriptAnalyzer singular-noun rule); `Invoke-WslRootScript` is `Invoke-WslBashScript -User root` because Stage 4 needs the same function as the default user.
- Branch carries unrelated uncommitted work (README, flake, scripts, tests). Only `git add` files this plan names; README is already dirty, so its edit stays uncommitted and is reported.
- Commit style: `type: imperative summary`, trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. `.wslconfig` with CRLF endings, spaces around `=`, or `NAT` in mixed case: merge must still find and replace in place (Task 1 test).
2. SHA256SUMS lists `ubuntu-26.04.1-wsl-amd64.wsl.zsync` next to the image: parser must not match it (Task 1 test).
3. `wsl --version` captured output contains NUL bytes (UTF-16): version parser must strip them (Task 1 test).
4. Password with leading/trailing spaces, backslashes, or non-ASCII: payload builder must not alter it and output encoding must be UTF-8 (Task 1 test on payload, Task 2 sets `$OutputEncoding`).
5. `-Distro` with spaces or path characters would make a broken install directory: parameter validation rejects it before any prompt (Task 3 verification).

user=__USER__
{
if ! id "$user" >/dev/null 2>&1; then useradd --create-home --shell /bin/bash --groups sudo "$user"; fi

chmod 440 "/etc/sudoers.d/$user-dev-setup"
visudo -cf "/etc/sudoers.d/$user-dev-setup"
